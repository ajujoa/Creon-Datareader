# 2026-07-20 date 변환 오류 수정

## 증상
- DB에 `date=20260721` 데이터 존재 (오늘은 7/20, 7/21은 아직 오지 않음)
- `date=0` 인 종목 629개 / 545,874행 존재

## 원인

### Creon day_block 롤오버
Creon API의 day_block(날짜 시리얼)이 **같은 거래일 중** 74367→74368로 롤오버됨.

| day_block | 실제 날짜 | 설명 |
|---|---|---|
| 74354 | 2026-07-01 (수) | 기준 매핑 (base) |
| 74367 | 2026-07-20 (월) | 정상 — date_map에 존재 |
| **74368** | **2026-07-20 (월)** | **Creon 롤오버 — date_map에 없음 → fallback이 7/21로 오계산** |

### Fallback 산술 오류
`_upload_to_db`에서 `date_map`에 없는 새 day_block에 대해:

```python
offset = day_block - _DAY_BLOCK_BASE   # 74368 - 74354 = 14
while added < offset:                  # 14 business days
    cur_day += 1 day                   # → 2026-07-21 (화)
```

14 business days after July 1 = July 21. 하지만 Creon day_block 74368이 나타낸 데이터는 **실제로 같은 7/20 거래일**의 데이터였음.

### date_map 단일 참조종목 한계
`_build_date_map()`이 **하나의 참조종목**에서만 day_serial→date 매핑을 추출. 참조종목이 아직 해당 day_block을 가지지 않은 경우 `date_map` lookup 실패 → fallback 발동.

### date=0 발생 원인
629종목은 기존에 fallback 코드가 없던 시절 업로드되어 `date` 필드가 0으로 남음.

## 수정 내역

### 1. 코드 수정 — `creon_chart_down.py` (line 223)

```python
# ponytail: Creon day_block이 거래일 중 롤오버되면 미래 날짜가 계산됨 → today로 cap
today = int(datetime.now().strftime('%Y%m%d'))
if date_val > today:
    date_val = today
```

fallback으로 계산된 날짜가 오늘보다 미래면 **today로 cap**. Creon day_block이 거래일 중 롤오버되어도 정확한 날짜 유지.

### 2. DB 수정

| 단계 | SQL | 영향 | 비고 |
|---|---|---|---|
| 1 | `DELETE ... WHERE date=20260721 AND stock_code IN (Jul20 보유 종목)` | 206,938 rows | Jul20+Jul21 중복 2,015종목 → Jul21 중복 제거 |
| 2 | `UPDATE ... SET date=20260720 WHERE date=20260721` | 56,572 rows | Jul21만 있던 569종목 → Jul20으로 정정 |
| 3 | `UPDATE ... JOIN ref_stock ... SET t.date = ref.date WHERE t.date=0` | 545,874 rows | date=0 629종목 → 참조종목 매핑으로 정상화 |

### 최종 상태
- `date=20260721`: **0 rows**
- `date=0`: **0 rows**
- total: 2,878 stocks / 144,112,285 rows
- Jul 20 (오늘): **2,642 stocks / 333,450 rows** (09:00~15:30)

## 향후 개선 포인트
- `_build_date_map()`: 단일 참조종목 대신 모든 종목의 day_block→date 집계로 보강 가능 (필요시)
- Creon day_block과 calendar date의 완벽한 매핑이 필요해지면 `_build_date_map`을 full-scan 방식으로 개선
